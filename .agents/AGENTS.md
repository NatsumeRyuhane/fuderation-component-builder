# Fuderation Workshop Component

This repository is a **one-component-per-repo template** for building a single
Fuderation Workshop component — an interactive UI widget that renders inside a
chat message in a storyline. Author source in `src/`; `npm run build` assembles
the importable `component.json`.

## Skills

When working in this repo, always load and follow these skills:

- **fuderation-component-builder** — the primary workflow for creating, debugging, and iterating on the component. Defines the `src/` authoring convention, the build (`npm run build` → `component.json`), the bridge function DSL reference, and the phased build process. Its `RUNTIME_INTERNALS.md` records reverse-engineered runtime behaviour, `EXAMPLES.md` collects annotated real components, and `reference/` vendors the official guide.
- **frontend-design** — design tokens, component patterns, and styling constraints. Use when writing or refining the HTML/CSS.

## Project structure

```text
src/
  markup.html      # HTML comments stripped  -> component.html   (then trimmed)
  styles.css       # CSS comments stripped   -> component.css    (then trimmed)
  script.ts | .js  # TS compiled+minified OR JS stripped + iframe locals renamed -> component.script
  ai_prompt.md     # AI supplementary prompt -> component.ai_prompt
  meta.json        # { "name", "description" }
component.json     # build output (generated, gitignored) — import into Workshop
```

## Rules

- Follow the phased build workflow from `fuderation-component-builder` — do not jump straight to a finished component.
- Author in `src/`; never hand-edit `component.json` (it is generated by `npm run build`).
- Use **either** `src/script.js` (comments stripped, eligible iframe locals renamed; reaches DSL mode only if every statement is a whitelisted bridge call) **or** `src/script.ts` (compiled by esbuild — compiled output always trips the native-JS detector, so iframe mode) — never both. Bridge functions are injected globals; never `import` them.
- **Know which render mode the component lands in.** `npm run build` prints it. DSL mode flattens CSS into inline styles (1000-char cap, no `@`-rules, no `:hover`) and runs the script on click; iframe mode gives a real stylesheet and runs on mount, but has no `openUrl` and makes the storage/world-info/progress/wait bridges async.
- **Only `script.ts` receives full minification.** HTML/CSS/DSL scripts lose comments and outer whitespace only. Iframe `script.js` also shortens eligible local names using Terser for scope analysis and verified source edits for output. Preserve top-level/public names, properties, shorthand bindings, function/class names, labels, private names, dollar-bearing identifiers, strings and formatting. `meta.json` may set `build.renameIdentifiers: false` or `build.reservedNames: [...]`; these settings are not exported and do not affect TypeScript. Disable renaming for scripts that inspect function source via `toString()`. Necessary JS line breaks/spaces and empty CSS/HTML comment separators remain. Budgets and mode analysis use processed output. Keep embedded JS/CSS in their own files. Never syntax-minify DSL scripts or merge bridge calls. Use `(() => {})();` to explicitly select iframe mode; renaming preserves the detected mode.
- When the user provides existing component code, split it into the `src/` files before making changes.
- Keep styles chat-bubble-friendly. No networking, no external fonts, no real auth, no real payment.
- Run `npm run build` after changes, confirm it passes validation, and address the warnings it prints — they flag silently-broken output, not style nits.
- Run `npm test` and `npm run typecheck` when changing the build pipeline.
- Use `npm run preview` to render `src/` locally through the real (vendored) runtime in a mock chat bubble — it shows the resolved mode, CSS truncation, auto-downscale at narrow widths, and a live host bridge. `vendor/` holds third-party code and is **not** covered by this repo's MIT license; see `vendor/README.md`.
- CI: pushing to `main` runs `.github/workflows/build.yml`, which rebuilds and commits `component.json` back to `main`; pull requests validate the build only. Do not hand-commit `component.json`.
